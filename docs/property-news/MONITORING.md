# Monitoring

The `source_fetch_runs` table and `news_events` audit stream support an eventual internal dashboard. `GET /api/admin/sources/health` exposes the protected Phase 1 health summary.

Track for each source: last successful/failed fetch, source age/staleness, error rate, response/parser failures, discovered count, duplicates, new items, and duration. Track the editorial pipeline: irrelevant/archived items, pending review, published/rejected items, AI/schema failures, risk distribution, average processing time, and cost per published item once an AI provider is configured.

Every collection response and GitHub Actions step summary reports active sources, due sources, attempted sources, and due sources deferred by the per-group limit. Summaries also distinguish URL discovery/rejection, article fetch/parse/rejection, insertion, duplicates, and processing failures. Failed-source names and classified failure categories are included in collection responses and the Actions summary; aggregate 403, 404, timeout, and oversized-response counts are also reported. Raw upstream error text is intentionally omitted from the workflow response. Any deferred due source fails the workflow so a group cannot silently remain partially unprocessed. A group failure rate of 25% or more also fails the workflow; lower partial failure rates remain warnings with explicit counts. Item-processing failures fail the workflow and are logged with the affected item ID and exception type. GitHub Actions serializes all scheduled and manually dispatched collector workflow runs through one concurrency group. The workflow is scheduled twice hourly at minutes 17 and 47 UTC; GitHub scheduling remains best-effort, so monitor actual run cadence rather than treating the cron expression as an execution guarantee.

Alert when a tier-1 source has not completed successfully within twice its configured interval, when failure rate breaches an agreed threshold, or when critical/pending content ages beyond a review SLA. Daily health jobs should read the same tables and alert a private operational channel; no alert integration is configured in Phase 1.
